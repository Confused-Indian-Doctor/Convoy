# Android map download runtime

The app ships a small, checksum-pinned `uk-map-manifest.json` catalog. The actual PMTiles are public, immutable release assets; they are not bundled into the APK. `MapDownloads.refreshManifest` explicitly refreshes the catalog over HTTPS from the separate `uk-maps-v1` catalog release and atomically caches it. A failed refresh leaves the previously usable catalog intact. The consumer Download action is shown only when the manifest supplies complete, validated metadata.

`MapDownloadWorker` is a unique WorkManager job per region. It requires a connected network and owns a foreground **dataSync** notification with bytes, percentage and Cancel. Activity destruction and screen navigation do not own or cancel the work. Android notification permission is requested by the download UI where applicable; notifications never contain convoy material. This worker is independent of ConvoyService and its GPS, microphone and networking leases.

The transfer engine follows at most five HTTPS redirects, requests identity encoding, enforces the declared maximum byte count and checks the complete SHA-256 from the trusted catalog. A partial file is resumed only when its catalog fingerprint still matches and a strong ETag was saved. Range responses must contain the exact starting byte, total length and unchanged ETag. A server returning HTTP 200 instead restarts the transfer safely. A server without a strong ETag restarts on retry. Temporary network errors, HTTP 408, 429 and 5xx retry with WorkManager exponential backoff, starting at 30 seconds, for at most six attempts. A transfer checkpoints after 50 minutes so extremely slow downloads do not occupy one foreground run indefinitely. Cancelled/interrupted partial files stay private and may be resumed by a later Retry; they never become active maps.

Android 15/16 enforce system background and dataSync time quotas. Convoy respects WorkManager/system stops and retains partial state. A queued/retrying download may therefore wait for connectivity or system scheduling. Opening Convoy and retrying is appropriate after a permanent failure; no task bypasses Android Wi-Fi or notification controls.

Before transfer, the engine checks actual device free space for the **remaining new-file bytes plus 64 MiB reserve**. For updates, the old installed generation already consumes device storage and remains intact throughout transfer; it is not reclaimed early. Downloads and installed files reside on the same private filesystem, so final atomic rename needs no second full-file copy. The UI reports actual maps, partial downloads, extracted routing/search data, GPX routes and free space. APK-contained assets are part of application installation rather than fictitious private-file counts.

Installation checks PMTiles v3 magic, vector tile type, compression, section ranges and overlaps, counts, bounded directory entries, strict bounded JSON metadata, geographic bounds and zooms. Official packs additionally require exact manifest size, digest, bounds and zoom limits, compatible UK region identity and UK extract extent. Only a fully checked new generation is atomically committed into `maps/uk/<region>/` with an atomic catalog. A failure or cancellation before catalog commit leaves the old map selected and usable. Successful install does not force selection; viewport/location/GPX coverage chooses a covering pack. The existing custom import and bundled Shrewsbury development regression pack remain supported.

Basemap icons/labels are rendered POIs. They do not create a searchable places database or a driving graph. Current UK regional downloads advertise rendered POIs but no independent search or routing installation. The existing Shrewsbury search/routing dataset remains separately bounded. GPX display and following are independent of either dataset.

Region suggestions use approximate country-border polylines to distinguish overlapping rectangular extracts; PMTiles header bounds remain the authority for installed tile coverage. Border areas deliberately overlap to avoid holes. The automated map-source build and observed byte sizes/zoom comparisons are documented in [uk-map-packs.md](uk-map-packs.md).

Host regression checks run with `tools/run_map_download_tests.sh` and exercise real parser/engine/store code through deterministic failed/cancelled/resumed HTTP responses, corrupt PMTiles, checksum failures, atomic replacement, storage checks, coverage and the published catalog. Android foreground scheduling and real downloads are separately exercised by emulator smoke tests; unit results do not claim physical-device scheduling behaviour.
